Real integration tests also need an explicit `PIXLET` executable with a maximum-duration flag and permission to bind a loopback port. An unset, unavailable or protected-install `PIXLET` produces an explicit skip. No external service, credentials or device is needed.

Publication regressions also exercise the public gateway URLs entirely through the fake HTTP layer, optional full-quotes/base overrides, strict loopback rejection, the secret-key schema and 100-symbol validation, BASIC's two-hour HTTP TTL (paid stays nine minutes), and byte identity between the root and publish app copies. `test_logic.py` executes the Python-compatible Starlark source using small Pixlet module doubles. It covers request rotation, immediate cache writes, the five-request cap, the roughly 15-second budget and five-second timeout reserve, cached failure fallback, state handoff and short-dwell sizing. This does not substitute for Pixlet's interpreter or image encoder.

Both Python suites cover indices on/off, default-on and page-one ordering; the shared budget of one indices batch plus at most four five-ticker quote chunks; BASIC's single ticker request with cached/no-data indices; independent indices failure handling; ticker-only offsets and toggle changes; absence of CLOSED headers and page-number footers; unknown plans paging beyond five tickers; later BASIC identification or quota fallback; successful BASIC responses without upgrade notices; quota pauses; and burst 429s without quota copy or BASIC fallback. The offline suite also checks malformed indices, old/stale dimming, immediate indices writes, missing indices waking covered quotes off-hours, origin quota errors and strict whole-URL loopback matching. Short-dwell tests reclaim the removed footer row while preserving room for useful status.

Unknown plans use the paid fetch window and schedule until a positive BASIC limit or actual quota exhaustion is observed. Confirmed BASIC uses only its first-chunk ticker probe per free slot and the five-call daily guard; enabling indices never adds a second request. Successful responses never add PRO/upgrade notices. Burst rate limits and quota exhaustion have separate assertions.

Quota notices and the no-key setup screen share `UPGRADE_URL` as a 64px `Marquee` child. Both suites check that successful BASIC/paid/unknown responses and burst 429s omit the link. Empty, omitted and whitespace-only keys show setup/free-key text and the marquee with zero requests, no cache writes, unchanged page/plan state and exactly one STATE line. Present keys retain both headers and the quotes/indices requests. Tight-dwell quota pages inline only a short summary; dedicated URL pages reserve the full scroll before allocating static page time. The real encoder checks total duration and enough frames held for at least 1500ms (or the existing sub-3s indices allowance) to retain every ticker/indices page; short marquee frames are checked separately. The setup scroll must complete within 3–5 seconds.

Indices cases assert one five-symbol batch (`DJI,SPX,NDX,RUT,VIX`), five ordered 6px rows plus 1px top padding, signed point changes and their colors (including RUT `+19` and VIX `+0.4`), numeric price-minus-previous-close fallback, neutral `--` for unavailable changes while preserving percentages, tiny moves, and stale/old dimming. Omitted or unusable RUT/VIX entries retain no-data rows while other indices and ticker pages render. Offline cache coverage checks require a dict for every listed index before suppressing an off-hours fetch. Ticker middle cells must still contain prices. Missing session fields do not close indices.

Review regressions cover successful 200 data with zero remaining (no pause or notices, while positive BASIC limits may be learned), failed quota responses that still pause, and the exact "Per-second quota exceeded" 429 with positive plan remaining and exhausted short burst headers for unknown and paid plans. The offline regex double returns captured groups only, with empty strings for unmatched optional groups and an empty list for no match; loopback validation would fail its tests if it compared the first capture to the full URL.

The HTTP doubles distinguish `/v1/quotes` from `/v1/indices`, record endpoint plus symbols, and use endpoint-specific cache keys/payloads. Tests disable indices by default (`False` in the Python Config); indices cases opt in, and default-on cases omit the setting.

Both suites check that empty 401 and HTML 403 responses from quotes or indices show KEY REJECTED before any quote data arrives. RapidAPI `message` rejections release unbilled claims only when no fresh request has succeeded; a fresh 200 with empty data still spends its claim. Bare origin rejections retain claims. Rejections after quotes arrive preserve those quotes and stop further requests. The offline suite also checks cached gateway rejections and documents that quota wording takes precedence over KEY REJECTED. Publication checks require the free-key description and plan-neutral settings help.
